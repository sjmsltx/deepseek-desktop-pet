## 一、错在哪

我在 v2 交接件里写了：

> ⑤「83%」是组维度不是条维度 | 已改（83% 组 / 71% 条） | **核验：15 单体组 + 3 组×2 条 = 21 条 ✓**

那个「✓」核错了对象。我当时只是把数字加起来对上了 21，**没查那 3 个「2 条组」到底是什么**。

WX-179 指出它们是**同一个 id 的两份**。我按 `real-groups.json` 复算，确认：

| 组（topic） | 条数 | 唯一 id | 真相 |

| `比较主流AI模型` | 2 | **1** | 同 id 两份：**关心桌宠身体健康** / 了解主流 AI 模型 —— **完全无关** |

第三组最能说明问题：因为撞号，一句「关心桌宠身体健康」被归到了 topic「比较主流AI模型」下面。
**这不是「一件事的两个方面」，这是 id 撞号的伪影。**

## 三、根因不是标注，是写入

这 3 组伪影的源头是 `memory_store.remember_fact` 里 id 生成无撞号检查：

```python
fid = f'f{int(datetime.datetime.now().timestamp() * 1000)}'
```

同一毫秒连写必然撞号（自动抽取一批多条正是这个场景）。存量已撞 3 组。
**同一处代码还藏着 50 条物理截断** —— 两个缺陷同源，都在这个函数里，见 WX-179 §一、§二。

已于 2026-11-05 一并修复（`_next_fact_id` + 删除物理截断）。

## 四、我这次错的性质

**不是算错，是没问「这 3 组是什么就核了」。**

组大小之和 = 21，条数对上了，我就打了 ✓。
但「对得上」只证明**数字自洽**，不证明**分组有意义**。
这和我在 313 §3 写过的规矩是同一个毛病：

> 判据必须能区分你想区分的两个选项。

我当时的核验只能区分「组大小之和是否等于 21」，不能区分「这 21 条是 18 件独立的事还是 21 条记忆」。
**它没能区分「多面向」与「撞号」，所以我那个 ✓ 什么也没证明。**

更难堪的是：WX-178 只说了「83% 是组维度」，是我自己去核的 71%。
如果当时多看一眼那 3 组是什么，缺陷②昨天就该被发现 —— **我复核了一个数字，却没复核它背后的实体。**
