## 四、代价：三个必须一起报的数

### 4.1 延迟（能放进主流程）

| 项 | 数值 |
|---|---|
| tokenizer 加载 | 7 ms |
| onnx 会话创建 | **72 ms** |
| **冷启动合计** | **79 ms** |
| 单次 query（21 条库） | 3.25 ms（p90 3.52） |
| 单次 query（1411 条库） | 3.88 ms（p90 4.54） |
| 单次 query（20000 条库） | 5.42 ms（p90 6.05） |

⇒ 79ms 冷启动、~4ms 每问，桌宠可以接受（它是常驻进程，只需加载一次）。

### 4.2 注入率涨的那 5 点是什么（**这是真代价**）

BM25 不注入、向量注入 = 11 条（31%→36% 净增来自其中一部分）：

| 用户消息 | cos | 注入的记忆 | 是否合理 |
|---|---|---|---|
| 「hello」 | 0.504 | 用户在学习/练习 Python | **✗ 明显误注入** |
| 「GEOGRAPHY」 | 0.519 | 用户喜欢玩 galgame | **✗ 误注入** |
| 「上难度，带数字标点」 | 0.546 | 用户经常发教材插图让桌宠识别 | **✗ 牵强** |
| 「你们服务器修好了吗」 | 0.505 | 用户会主动关心桌宠、语气友善 | **✗ 误注入** |
| 「>>> d={x:y for x in ...}」 | 0.612 | 用户在练习 Python | **✓ 合理** |
| 「你刚刚发的那个字典程序没法输入」 | 0.612 | 用户在练习 Python | **✓ 合理** |
| 「写一段摩斯编码的字典」 | 0.586 | 用户在练习 Python | **✓ 合理** |
| 「再背」 | 0.506 | 用户爱背古文 | △ 勉强 |
| 其余 3 条 | 0.505~0.525 | — | ✗ 偏误 |

反过来，向量**丢掉** 4 条 BM25 原本会注入的：

| 用户消息 | BM25 注入 | 判断 |
|---|---|---|
| 「说话」 | 用户说话语气友善 | ✓ 丢了更好（本就误注入） |
| 「PYTHON 3.14!」 | Python 满分记录 | ✗ 不该丢 |
| 「GIS? 4326 / 3857?」 | 重庆区县地理数据分析 | ✗ 不该丢 |
| 「牛逼，我以为你要选claude或者gpt」 | 了解主流 AI 模型 | ✗ 不该丢 |

**净判断**：新增的偏误多于丢掉的正确 ⇒ 注入质量没有变好，只是量变了。
这就是「记忆过拟合」的回归风险，必须承认。

### 4.3 库变大后阈值还成立吗

| 库 | top1 余弦 最小 / 中位 / 最大 |
|---|---|
| 真实库 21 条 | 0.439 / **0.604** / 0.646 |
| 合成库 1411 条 | 0.458 / **0.587** / 0.666 |

⇒ 中位几乎不变（0.604 vs 0.587），**库变大不会把余弦整体抬高**，阈值可迁移。

⚠ 注意：这不证明「1411 条里能找回答案」——那 1411 条是无关合成库，本来就没有这些事实。
上一版我拿真实库期望去合成库找、找不到就说「大库不灵」，那是**测试设计错误**，已撤回。

## 五、硬条件：为什么必须配「定义式提问」守卫

这是本轮最重要的发现，也是一个**结构性冲突**。

在 `CONTRACT_FACTS`（2 条虚构数据）上实测余弦：

| 查询 | top1 cos | 命中 | 契约要求 |
|---|---|---|---|
| 「扫雷是什么」 | **0.5548** | 用户喜欢玩扫雷和 Farkle 骰子 | **必须挡住** |
| 「介绍一下骰子」 | **0.5864** | 同上 | **必须挡住** |
| 「考研数学二复习计划怎么安排」 | **0.7715** | 考研目标那条 | 必须放行 |

**语义检索没有任何理由区分「在问概念」和「在问我」。** 字面判据天然挡得住
（只共享 1 个 2-gram ⇒ coverage 0.25 < 0.30），向量判据则把两者放在同一个方向。

所以有两条路：

| 做法 | 阈值约束 | holdR@3 | 结论 |
|---|---|---|---|
| 只调阈值 | 必须 **> 0.5864** 才挡得住「介绍一下骰子」 | 5/12 = 42% | **等于没进步** |
| 阈值 + 句式守卫 | 可降到 0.51 | **11/12 = 92%** | **唯一可行** |

句式守卫 = 命中「是什么/是啥/什么意思/介绍一下/讲讲/科普」等 → 本轮不注入。

⚠ 但守卫是**硬编码规则，覆盖不全**：「扫雷怎么玩」「骰子规则」不匹配这些词，
仍会被注入。这是遗留风险，必须记着。

## 六、结论与建议

### 6.1 符合预期吗：符合，且超出

| 指标 | 基线 | 向量 0.51 | 变化 |
|---|---|---|---|
| 留出集 R@3 | 3/12 = 25% | **11/12 = 92%** | **+67 点** |
| 闸门全关上限 | 5/12 = 42% | — | **已越过** |
| 开发集 R@3 | 2/6 = 33% | 5/6 = 83% | +50 点 |
| 纯噪声 | 0 | 0 | 持平 |
| 注入率 | 31% | 36% | +5 点 |
| 契约 | 过 | 过（靠守卫） | 需守卫 |

### 6.2 采纳的参数

```
模型     bge-small-zh-v1.5 int8 ONNX（22.9MB，MIT，512 维）
阈值     cosine ≥ 0.51
守卫     定义式提问（是什么/是啥/什么意思/介绍一下/讲讲/科普…）→ 不注入
回退     模型缺失或加载失败 → 原地回到 BM25（功能不消失）
```

### 6.3 三条工程约束（不变，另加一条）

1. **可选组件 + 优雅降级**：加载失败回退 BM25，不抛错、不阻塞启动
2. **增量编码 + 持久化**：只给新记忆算（2.64ms/条），向量存旁文件；
   模型或参数变了要检测并重算（否则新旧向量不在同一空间，cosine 无意义）
3. **阈值可重校准**：本轮三个脚本留着，换模型/改参数后重跑
4. **新增：句式守卫必须与阈值同批上线** —— 只改阈值不加上守卫，会违反
   「记忆只作背景、不做话题」这条硬约束（`test_memory_gate.py` 的语义契约）

### 6.4 仍存在的风险

| 风险 | 说明 |
|---|---|
| 样本太小 | 留出集只有 12 条，92% = 11/12，置信区间很宽。别当精确值引用 |
| 0.51 在陡坡上 | 0.50→47% 注入、0.51→36%、0.52→83% 召回。**移动 0.01 就跨界** |
| 守卫覆盖不全 | 「扫雷怎么玩」这类不匹配定义式词表，仍会注入 |
| 注入质量未改善 | §4.2 显示新增的偏误多于丢掉的正确 |
| 未测 | 与 BM25 加权融合（RRF）没试；多语言/英文场景没测 |

## 八、本轮踩的两个坑（都是我自己的错）

1. **契约口径写错**：第一版用真实库（21 条）测「扫雷是什么」，而真实库里
   **没有扫雷那条**（它在 `CONTRACT_FACTS` 虚构数据里）⇒ 必然返回空 ⇒
   「契约通过」是**假通过**。改用 `run_study.CONTRACT_FACTS` 后才发现
   「扫雷是什么」cos 0.5548、「介绍一下骰子」0.5864，阈值必须配守卫。
   （教训：验证脚本的「通过」要先问一句「这个夹具真的能跑到失败分支吗」）

2. **测试设计错**：拿真实库的期望答案去 1411 条**无关合成库**里找，找不到
   就说「大库不灵」。合成库里本来就没有这些内容 ⇒ 那个结论无效，已撤回。
   改成只测「top1 余弦是否随库大小漂移」，这才是阈值迁移的真问题。
