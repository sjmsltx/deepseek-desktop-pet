# 「自改代码」功能诊断报告（2026-09-15）

> 🔒 本文已脱敏（移除本地路径与个人信息）。

> 触发：使用者反馈「以前多个版本测试，这个功能总会出问题，几乎没成功过」。
> 方法：读实现（pet_selfcode.py）+ 跑现有单测（12 组全过）+ **沙箱复现**（临时 git 仓库 / 非 git 目录 / CRLF 文件）+ 打包产物核对。
> 结论：**单测全过但真实使用几乎必败** —— 因为 12 组单测只覆盖"拒绝分支"，**没有覆盖"成功路径"**，而失败点全在成功路径上，且被静默吞掉。

---

## 一、四个根因（按影响排序）

### 🔴 R1（致命）打包版（冻结环境）100% 不可用 —— 两道闸门同时拦死

| 闸门 | 代码位置 | 冻结环境下的实际行为 |
|---|---|---|
| git 基线检查 | L102 `git rev-parse --is-inside-work-tree`（cwd=base_dir） | 打包产物 `dist/DeepSeekPet/` **没有 `.git`**（已核对：`.git 存在 = False`）→ 直接返回「不是 git 仓库，拒绝自改」 |
| 语法校验 | L156-159 `subprocess.run([sys.executable, '-c', 'ast.parse...'])` | 冻结后 `sys.executable` **就是桌宠 exe**（已核对：dist 内 `python*.exe 数量 = 0`）→ 校验命令等于"再启动一只桌宠"，必然失败/超时 |

**⇒ 只要在打包版里试这个功能，一次都不可能成功。** 这解释了"几乎没成功过"。

### 🔴 R2 备份（双保险）从来没生效，而且**返回消息还在撒谎**

- L119 `shutil.copy2(path, … datetime.datetime.now() …)` —— 全文件 **没有 `import datetime`**（只有 os/re/subprocess/shimutil/sys）
- → `NameError` 被 L120 的 `except Exception: pass` 静默吞掉
- **实测证据**（沙箱 A 组）：编辑成功，`backup/` 目录被创建，**里面文件数 = 0**
- 而返回文本是：`✅ 已修改（回滚：可用 backup/ 备份文件恢复 或 backup/ 备份）…` ← **提示了一个不存在的备份**

### 🟠 R3 行尾被整体改写（CRLF → LF）

- L123 读用 `newline=''`，L128 `splitlines()`，L134 `'\n'.join(...)` → 整个文件的行尾被统一成 LF
- **实测证据**（沙箱 C 组）：编辑前 `A = 1\r\nB = 2\r\nC = 3\r\n`（3 个 CRLF）→ 编辑后 `A = 1\nB = 22\nC = 3\n`（**0 个 CRLF**）
- 后果：git 里显示"整个文件都改了"（diff 爆炸、审查与回滚都变难）；若与 `core.autocrlf` 交互，还会产生噪音改动

### 🟠 R4 全链路静默（出问题无处查）

- 4 处 `except Exception: pass`：L44-45（搜索）、L78-79（写文件工具）、L112-113（hash）、L120-121（备份）
- 失败时既不写日志、也不告诉 AI/使用者 → "没成功"但**什么都查不到**（与本次排障的另一条主线同源）

## 二、次要问题（影响体验，不是致命）

| # | 问题 | 说明 |
|---|---|---|
| S1 | 12 组单测只测"拒绝分支" | `test_pet_selfcode.py` 覆盖的是"不允许改的文件/路径穿越/语法错误"等，**成功路径 0 覆盖** → 单测全绿 ≠ 功能可用 |
| S2 | 感知落差 | 改完必须**重启桌宠**才生效；提示语虽写了"请重启"，但没说明"改了哪个文件第几行"，使用者容易认为"没成功" |
| S3 | 依赖外部 `git` 命令 | 若 git 不在 PATH（或换了环境），git 检查/回滚建议都会落空 |
| S4 | `search_code` 只扫顶层目录 | 不递归子目录 → 代码搬进子目录后会"搜不到" |
| S5 | 无法在改后自校验 | 只做了 `ast.parse`（语法级），没有做"目标逻辑是否真的被替换"的语义级校验 |

## 四、一句话总结

> **功能不是"经常出 bug"，而是"在打包版里必然失败 + 成功路径零测试 + 失败全程静默 + 备份其实一直是坏的"。**
> 前三条修完（约 20 行改动），这个功能才算真的可用；第 P2 条（补成功路径测试）是防止它再退化的关键。
