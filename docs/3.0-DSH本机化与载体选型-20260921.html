DSH 本机化与载体选型

不再用虚拟机：把 DSH 装到本机；桌宠只当桌面外壳、不碰 agent 能力，避免双 harness 打架；顺带纠正"群聊吃内存"与"共用 API key"的认知。

日期 2026-09-21 ｜ 依据：npm registry 实测 / DSH 官方文档 / 本机与 VirtualBox 实测
安装：@deepseek-ai/dsh@0.1.5-rc.2 → <DSH 安装目录>（独立目录，不改 AutoClaw 的 Node）

01决定：升到哪个版本

你原话是"升到较新的 rc"，npm 上的标签正好对得上 —— 所以取 0.1.5-rc.2，它是 latest 标签，比 alpha 稳、接口更定型。

npm 共 22 个版本（0.1.2-alpha.2 起）；包内可执行文件 dsh → lib/bin.js；依赖 72 个。

02为什么"拉到本机"是对的

但要说清理由：不是为了省群聊的内存（见第 05 节），而是 —— 少一层虚拟化 + 少一条 SSH 隧道，启动更快、调试直接、备份简单，且不再让虚拟机白占 4 GB。

先别动虚拟机 虚拟机现在 poweroff，磁盘里 6.34 GB 是那台机器的整套环境。它里面有你可能已经配好的 DSH 设置与凭据（本机 ~/.dsh 目前不存在，是全新的）。
建议：本机跑通后再决定是否启动虚拟机、把 ~/.dsh 配置与工作区拷过来；先不删虚拟机（它是唯一的配置备份）。

03安装与启动

# 安装（独立目录，不污染 AutoClaw 自带 Node）
npm install -g --prefix "" @deepseek-ai/dsh@0.1.5-rc.2

# 启动（Web UI 默认 127.0.0.1:3080，--no-open 不自动开浏览器）
"<DSH 安装目录>\dsh.cmd" web --no-open

对比原虚拟机方案：原来要 VBoxManage startvm → 等 25 秒开机 → SSH 进 2222 起服务 → 再建 3080 隧道 → 才开浏览器（就是桌面上那个 启动DSH.bat 的四步）。本机化之后只剩最后一步。

04桌宠自动读取 DSH 配置与技能（可行，但有铁律）

你的判断是对的：桌宠本身也算一个 harness，深度融合会和 DSH 打架。冲突点具体是四个：

冲突面桌宠侧DSH 侧裁决
Agent 循环自带对话/工具调用自带 agent loop + 工具归 DSH
模型配置models.json$DSH_HOME/settings.yaml归 DSH，桌宠只读
记忆memories.json / 好感度工作区 + mcp-memory各管各的，互不写
权限/审批自带治理层与审计自带权限模式与沙箱各管各的，不交叉授权
铁律：单一事实来源 桌宠对 DSH 的配置与能力清单只做只读镜像、不做双写。DSH 是模型/提供方/技能/工作区的唯一事实来源，桌宠负责"看得见"（展示 + 一键打开），不负责"改得动"。这样两边永远不会因为各存一份而漂移。

能读到什么、从哪读

要读的东西位置（官方文档口径）
模型 / 提供方 / 推理等级 / 超时重试$DSH_HOME/settings.yaml（模型页写的就是这份文档）
API 密钥$DSH_HOME/.credentials.yaml（只写；页面只拿到脱敏描述符）→ 桌宠绝对不读这份
技能 / 插件清单随版本演进，优先走 DSH 本地服务的接口或工作区目录，而不是自己解析内部文件

顺带一个好消息：DSH 原生支持多提供方与自定义网关 —— 内置 anthropic、openai、moonshotai(Kimi)、zai(GLM) 等，也能加自定义 OpenAI 兼容 / Anthropic 端点。多模型圆桌的 provider 配置可以直接复用 DSH 已有的这套，我们不必再造一套密钥管理。

05纠正："群聊吃内存"和"共用 API key"

结论 只要模型跑在云端，角色数量、厂商数量、key 数量对"本机内存"几乎没有影响；它们影响的是限流、配额、账单归属。本机内存真正吃紧的是浏览器/WebUI 与 Node 进程本身。
你问的会不会降低内存真实影响
同一家厂商同一个 key不会反而更容易撞同一个账号的 RPM/TPM 限流 → 多角色并发时更早 429 ✗
同一家厂商多个 key不会扩容并发 + 隔离配额 + 方便按角色分账 ✓（不省内存）
少接几个角色影响很小省的是 token 成本与墙上时间，不是内存
本地跑模型（离线）大幅增加占用这才吃显存/内存；本机 8 GB 显存 → 只到 7B~8B Q4

所以群聊真正该设的闸门不是"省内存"，而是控成本和控收敛：角色数（先 2~3 个）、单议题回合上限、单议题 token/金额上限、连续无新信息即收束、人类消息可随时插队暂停。

推荐 B：你这轮的核心诉求是"桌宠单纯当个桌面形式、不要和 DSH 冲突"，进程隔离是最彻底的隔离；壳用系统 WebView2 先做最小实现，将来要托盘/自动更新再考虑 Tauri。桌宠负责立绘、语音、本地能力与"打开 DSH 面板"的指令，两边用本地接口联络。
