# 主题 token 化 · A2-1 小游戏（2026-09-15）

> A2 第一段：把**小游戏**从"配色写死"改成"跟随主题"。

## 一、改前状况

`pet_minigames.py`（2014 行 / 19 个类 / 15 款游戏）里 **55 处硬编码颜色**，完全不接主题：
用户换成浅色主题后，聊天面板变了、一进小游戏还是深色 —— 割裂感很强。

## 二、做法

### 1. 主题通道（模块级快照 + 取色函数）

```python
from pet_theme import DEFAULT_THEME as _THEME_DEFAULT

_ACTIVE_THEME = dict(_THEME_DEFAULT)
_OPEN_GAMES = []                      # 已打开的游戏窗口

def set_theme(theme):                 # 宿主调用：更新快照 + 刷新已开窗口
    ...
def T(key, fallback='#ff00ff'):       # 小游戏内唯一取色入口
    return _ACTIVE_THEME.get(key) or _THEME_DEFAULT.get(key) or fallback
def refresh_open():                   # 已开窗口统一重刷
    ...
```

选择"模块级快照"而不是"给 19 个构造函数加 theme 参数"：改动面小一个数量级，且
`paintEvent` 类控件在绘制时现取色 → `update()` 一下就跟上主题。

### 2. 样式工厂（切主题可重刷）

子控件在创建时挂一个样式工厂 `widget._theme_qss = lambda: ...`，`BaseGame.apply_theme()`
遍历 `QPushButton` / `QLineEdit` 子控件重刷。这样**不需要给每个游戏类写 apply_theme 覆写**。

### 3. 多值色板 → token 映射

- 2048 的 13 档色阶：`_tile = {0: 'mg_input_bg', 2: 'mg_btn_bg', ...}` → 渲染时 `T()`
- 扫雷数字色 `{1..5}`：映射到 `mg_accent_soft/mg_green/mg_red_soft/mg_red/mg_purple`
- 俄罗斯方块方块色：`COLORS` 改存 **token 名**，绘制时解析
- 西蒙记忆色板：同上（存 token 名 + 名称）

### 4. token 表（`pet_theme.py`）

新增 **34 个 `mg_*` token**（含 2 个补漏：`mg_stone_dark='#111111'` 黑子、`mg_flash='#ffffff'` 闪烁），
并登记进 `TOKEN_GROUPS['minigame']`。**取值与原子面量逐项一致**。

### 5. 宿主接入

- `_apply_theme()` 末尾调 `_apply_minigame_theme()` → 推主题给小游戏模块并刷新已开窗口；
- `_open_games()` 开窗前先同步主题（新窗口一定吃到当前主题）；
- 启动恢复主题时同样走 `_apply_theme()` ✓。

## 四、后续修复（同日发现）

⚠️ **本段迁移引入过一个真 bug（已修）**：替换 import 块的锚点把
`from PySide6.QtGui import QPainter, QPen, QColor, QBrush` **整行吃掉了** →
所有画布类游戏（五子棋 / 扫雷 / 贪吃蛇 / 2048 / 俄罗斯方块…）的 `paintEvent` 抛 `NameError`，
对话框能打开但**画面全白**（使用者实测「游戏界面没了」）。

**教训**：当时所有测试只断言“能构造 / 样式表有色”，**抓不到绘制期错误**。
现已增加“真绘制”扫荡测试：`tests/test_minigames_paint.py`、`tests/test_ui_paint_sweep.py`
（对每个 UI 面真 `show + processEvents + grab`，并捕获 excepthook / stderr）。
