桌宠记忆重构 · 概念全解

从「为什么 LLM 需要记忆」到四层模型、检索、写入、注入——所有概念的体系化讲解（2026-08-31）

〇、地基：为什么 LLM 需要记忆系统

1. LLM 是无状态的

每次调用 API，模型只看到你这次请求里塞进去的文字，它不记得上一次对话。所谓「记忆」，本质是：把过去的对话/事实，整理后重新塞回这次请求的上下文里。

桌宠例子：你昨天说「我爱吃桃片」，今天问它「我爱吃什么」——它不知道，除非我们把「爱吃桃片」写进今天的请求。

2. 上下文窗口有限（token 是门票）

模型一次能读的文本量有限（DeepSeek 约 64k-128k token，1 个汉字 ≈ 1-2 token）。全部历史都塞进去：装不下（超限报错/截断）、很贵（按 token 计费）、还会让模型「分心」（检索质量随上下文膨胀退化——BEAM 基准结论）。

桌宠聊 1 个月，对话可能 20 万 token——不可能全塞，必须「挑重点」。挑重点 = 记忆系统。

3. 记忆系统解决什么

过去对话→整理（抽取/摘要）→存储（结构化）→检索（挑相关）→注入（塞回请求）

一、四层 Agentic Memory 模型（分类框架）

Futurum Research 2026 年提出的业界分类标准，把 Agent 记忆按「时效 + 用途」分四层：

层英文是什么桌宠对应存取速度
工作记忆Working当前对话上下文，用完即弃chat_history 最近 30 条最快（直接读）
情景记忆Episodic发生过的事（经历/事件）回忆日志 memories.json中（按事件检索）
语义记忆Semantic沉淀下来的事实/知识memory.json 用户事实慢（检索 top-k）
程序记忆Procedural技能/行为模式/规则「用户不懂英语」这类行为规则常驻
类比人脑：工作记忆 = 正在说的话；情景 = 「上周吃了火锅」；语义 = 「重庆是直辖市」；程序 = 会骑自行车。

二、存储层概念

结构化记忆Structured Memory
把散落对话提炼成「一条条有字段的记录」：内容、重要度、时间、归属角色、状态。字段化才能排序、筛选、检索。
桌宠事实：{ content: "用户爱吃桃片", importance: 5, roles: "both", status: "active", updated_at: "..." }
时间戳 / recency 加权Timestamp & Recency Weighting
每条记忆带时间。检索打分时，越新的记忆权重越高（指数衰减），因为「上周的喜好」比「去年的」更可能还成立。
用户说过「我爱喝冰美式」（昨天）和「我不喝咖啡了」（今天）——按 recency，今天这条优先，旧的下沉甚至淘汰。
软覆盖 / 遗忘机制Soft Overwrite & Forgetting
新信息与旧记忆冲突时：旧记录标记为 superseded（作废）而不是物理删除（可回溯）；超量时按重要度+旧 淘汰。
桌宠已有：新「下午上课」覆盖旧「下午没课」→ 旧标记作废。记忆超 50 条 → 优先淘汰「低重要度 + 很久没更新」的。
分层预算Layered Budget
prompt 空间有限，给不同层分配「注入额度」：core 常驻（用户画像，永远在）、检索层（按问题挑）、归档层（基本不注入）。
Letta 的设计：core memory（~1k 字符常驻）+ archival（按需检索）+ recall（对话回忆）。桌宠预算：core 400 + 检索 600 + 情景 3 条。

三、检索层概念（核心中的核心）

BM25 关键词检索Best Matching 25
经典文本检索算法（搜索界的常青树）。给每个词算分：词频（出现越多越相关）× 逆文档频率（越稀有的词越值钱，如「桃片」比「喜欢」值钱）+ 长度归一化。纯 Python 可写，零依赖。
问「我下午干什么」→ 分词（下午/干什么）→ 与记忆逐条算分 → 「下午上课」（命中「下午」）排前，「用户爱喝咖啡」得分低。
中文难点：需要分词。轻量做法 n-gram（把「下午上课」切成「下午」「午上」「上课」等片段）或内置常用词表。
Embedding / 向量化Embedding / Vectorization
把「文字」变成「一串数字（向量）」，让语义相近的句子向量距离近。如「下午的课」和「下午上课」向量很近（BM25 只能靠字面重合，embedding 懂意思）。
"我爱吃桃片" → [0.12, -0.34, 0.87, ...]（几百维数字）。「桃片」和「合川特产」向量距离近，即使字面不同。
余弦相似度Cosine Similarity
衡量两个向量「方向是否一致」：值 -1~1，越接近 1 越相似。向量检索就是：把问题向量化，和所有记忆向量算余弦，取 top-k。numpy 一行就能算，不需要数据库。
query 向量 vs 28 条记忆向量 → 28 个相似度 → 排序取前 3 条注入。
RAG（检索增强生成）Retrieval-Augmented Generation
不是某个具体技术，而是一种模式：生成前先检索——把检索到的资料/记忆塞进 prompt，让模型基于资料回答。桌宠记忆重构本质就是「给桌宠加一个 RAG 记忆通道」。
用户问 → 检索记忆（BM25/向量）→ 拼进 system prompt → AI 看到「用户下午上课」→ 回答「你下午有课呀」。
LLM 重排序Rerank
检索先粗筛（BM25/向量给 top-8），再用 LLM 精排：「以下候选记忆，哪些与问题最相关？选 3 条」。检索要快、重排要准，两级配合。
BM25 捞出 8 条（快）→ LLM 看 8 条选最相关的 3 条（准，多花 0.5k tokens）→ 只把 3 条注入。

四、写入层概念

自动抽取Memory Extraction
对话结束后，让 LLM 通读对话，提炼「值得长期记住的信息」，写成结构化记忆。mem0 的核心（add 方法）：抽取原则是 faithful（忠实原文，不脑补）。
对话「我下午上课，晚上去食堂」→ 抽取：「用户今天下午有课」。桌宠现在靠 AI 主动调 memorize，改成系统自动抽，不漏记。
记忆链接 / 去重合并Memory Linking & Dedup
新记忆与旧记忆相关时：合并更新而不是新增一条（避免「爱吃桃片」出现 5 条）。mem0 用图结构做 linking；桌宠用轻量规则（内容相似度/关键词命中）即可。
已有「用户爱吃桃片」→ 新对话「我更爱甜味桃片」→ 更新原条：content 合并为「用户爱吃桃片，尤其甜味」。

五、三个借鉴项目怎么落地这些概念

项目存储检索写入我们借鉴
mem0（~40k★）向量库 + 图向量相似度LLM 自动抽取 + 图去重自动抽取、去重合并、add/search 接口
Letta（~14k★）JSON（core/archival/recall）关键词 + 向量Agent 自我编辑记忆分层预算、常驻 core

桌宠取三者精华、去掉重型依赖：存储用 JSON（Letta 风格）+ 检索 BM25→向量（mem0 思路，环境允许后）+ 写入自动抽取（mem0）+ 注入分层预算（Letta）+ 时效加权（Zep）。

六、概念全景串联

对话→自动抽取(LLM)→结构化存储(字段+时间戳)→去重合并
用户提问→BM25 粗筛 top-8→(Phase2: 向量+余弦)→LLM 重排 top-3→recency 加权
注入：core 常驻(400)+检索 top-3(600)+情景最近3条→AI 回答

这就是「四层记忆 + RAG」的完整闭环：写（抽取→存储）→ 查（检索→重排）→ 用（分层注入）。
