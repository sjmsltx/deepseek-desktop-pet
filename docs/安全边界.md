## 六、真实案例（⭐ 制度文档里放真案例，比放抽象条款有用得多 ✓）

### 6.1 ⭐ `source_ref` 路径穿越（⭐ 越界读 ＋ 落盘 ✗ · 2026-10-05 微信侧实测 ✓）

- ⭐ **根因**：⭐ `asset_ops._find_source()` ⭐ 只做**前缀字符串判断** ✓ 之后直接 `os.path.join` ✗
- ⭐ **可越界**：⭐ `assets_3.0/../../<任意文件>` ⭐ **满足前缀** ✓ 但**规范化后已在仓库外** ✗
- ⭐ **可达路径**：⭐ 界面「资产矩阵」首图 `source_ref` → `POST /api/pending`（⭐ **不需要动作开关** ✗）→ ⭐ **把仓库外文件拷进 `assets/<role>/`** ✗
- ⭐ **修法**：⭐ **`realpath` 规范化 ＋ 断言仍在允许根之下** ✓（⭐ 不满足即拒 ＋ 落痕 ✓）＋ ⭐ 护栏（⭐ 含**反向**：合法路径必放行 ✓）
- ⭐ **教训**：⭐ ⭐ **前缀字符串判断 ≠ 路径安全** ✗ —— ⭐ 必须**规范化后**再判 ✓

### 6.2 ⭐ 文档含本机隐私（⭐ 开源阻断项 ✗ · 2026-10-05 微信侧 `precheck_release.py` 逮到 ✓）

- ⭐ **现象**：⭐ `ENTRY.md` 里 5 处写死 `<Windows 用户名>\...\python.exe` ✗
- ⭐ **风险**：⭐ 内容是"自己的启动命令"无可厚非 ✓，⭐ 但**一旦外发就泄露用户名与目录结构** ✗
- ⭐ **修法**：⭐ 换 ⭐ **`<你的 python 完整路径>`** 占位 ✓ ＋ ⭐ **保留知识**（"⛔ 不要用裸 `python` ✗ —— PATH 里可能是别家的"✓）
- ⭐ **顺带**：⭐ 全仓再扫又抓到 `tools/verify.py` 写死本机路径 ✗ ⇒ ⭐ 改 `PET_PY` → `sys.executable` ✓（⭐ **功能零损失** ✓）
- ⭐ **教训**：⭐ ⭐ 换掉路径，**别把知识一起换掉** ✓

### 6.3 ⭐ 共用工作区的**真实数据覆写**（⭐ 不可取回 ✗ · 2026-10-04 ✓）

- ⭐ **现象**：⭐ 我方用 `io.open(..., "w")` 覆盖了 **另一方当日的约 4 万字笔记** ✗
- ⭐ **根因**：⭐ **共用工区 ＋ 同名文件 ＋ 同语义** ✗（⭐ 不是"读了文件"，是**用写模式打开了他人的文件** ✓）
- ⭐ **修法**：⭐ ① 各自加**线名后缀** ✓ ② ⭐ **写前先看 mtime／大小** ✓ ③ ⭐ **不是我建的文件一律不用 `"w"` 打开** ✗ ④ ⭐ **同一语义的新文件也要先查** ✓
- ⭐ **教训**：⭐ ⭐ 共用目录里，"**同名**"和"**同语义**"都是危险信号 ✓

### 6.4 ⭐ 静默吞异常（⭐ 让问题**看不见** ✗ · 反复出现 ✓）

- ⭐ **现象**：⭐ 多次在"**给失败落痕的代码里**"写出 `except: pass` ✗（⭐ 甚至因此让一处新功能**静默失效** ✗）
- ⭐ **机制**：⭐ 已有护栏 ⭐ `test_silent_guard`（⭐ 基线冻结、只判新增 ✓）—— ⭐ **每次都抓到了** ✓
- ⭐ **教训**：⭐ ⭐ "落痕代码"里**最不该**出现静默 ✗；⭐ 且 ⭐ **失败必须可见** ✓（⭐ 这条是本项目最贵的教训之一 ✓）
