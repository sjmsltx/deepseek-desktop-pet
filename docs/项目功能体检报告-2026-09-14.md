## 四、产品定位适配性

**现状定位**（README）：桌面 AI **陪伴**助手 —— 双角色 · 长期记忆 · 工具调用 · 主动关心。

**适配判断（三条）**

1. **"陪伴链"的投资方向正确且稀缺**
   记忆 → 好感度 → 主动关心 → 小游戏 → 回忆相册，这条闭环在开源桌宠里罕见；15 款小游戏是别人抄不动的重资产。这部分与"陪伴"定位**高度一致**，建议继续加码。

2. **"工具"层与"陪伴"存在心智张力（最大的定位问题）**
   - 29 个工具的 schema = **11,115 字符 ≈ 5.5K token，每次请求都要带**
   - 打开程序 / 进程管理 / 剪贴板读写 / PowerShell 执行 —— 这些是"效率工具"心智，与"Q 版桌宠"人格互相拉扯
   - 上下文里工具说明 + 记忆块 + 关系回忆一起挤人设 → 直接后果就是用户反馈的**"性格单一"+"什么都往记忆/工具上靠"**
   - ⇒ **定位建议：明确"陪伴优先、工具为辅"**，工具做**梯级暴露**（默认只露 5–6 个高频陪伴型工具如 天气/提醒/待办/时间/音量；其余收进"进阶模式"开关或按需加载）——同时改善人格一致性、token 成本与"往工具跑"的倾向

3. **目标用户与差异化**
   - 目标用户：个人 PC（学生 / 开发者）—— 与作者自身画像吻合，利基但真实
   - 差异化：双角色 + 好感度成长 + 15 小游戏 + 主动关心
   - 现状信号：GitHub 11 stars / 0 fork / 0 issue → **是曝光不足，不是质量不足**（对应上次讨论的"缺的是让外面看见"）

**风险**：① DeepSeek API 依赖（改名/调价/限流全传导，档案化已挡一层）② 美术资产（37 状态 ×2 角色 + Live2D）是产能瓶颈 ③ 深绑 Windows（winmm/startfile/注册表自启），跨平台不可用。

## 五、优先级建议

**P0（本周内，成本低收益高）**
1. **打一次包并按 2.7.0 实测**（当前包落后一个月，是"能不能交付给别人用"的第一道门）
2. **补齐陪伴核心的最小测试**（好感度触发/阶段、主动关心判定、气泡渲染各 5–10 条断言）——覆盖最薄的地方恰是产品最核心处
3. **3 处非原子写**核实并改成 `atomic_write_json`

**P1（两周内）**
4. **工具梯级暴露**（默认 5–6 个 + 进阶开关）→ 省 4K+ token/请求、人格一致性↑

6. `__init__` 312 行拆分（子系统装配拆成 `_init_*` 或独立模块）——注意按"高变更率优先"，别为拆而拆

**P2**
7. CHANGELOG 补 2.7.1（含本次 P0 修复 + 记忆治理）+ 打 GitHub Release
8. 本地 API key 加固（Windows 凭据管理器 / DPAPI）
9. 跨平台评估（若真要对外，先把 win32 依赖隔离成 `platform/` 层）
