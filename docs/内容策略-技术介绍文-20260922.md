# 内容策略 · 技术介绍文 → 产品文 → 更新文(2026-09-22 定)

> 触发:使用者复盘两次投稿的**实测差距** --
> · 纯「更新了哪些东西」的推文:**300+ 阅读** ✗
> · 首次「产品全貌」式推文:**6.8 万阅读 + 数百赞同收藏** ✓
> **差距 226 倍**,且这不是标题技巧,是**叙事结构**问题。

---

## 一、四条硬规则

| # | 规则 | 依据 |
|---|---|---|
| 1 | **更新文不得作为入口** -- 先讲"这是个什么东西、解决谁的什么问题",再讲这次改了什么 | 路人视角:只看到一堆术语更新 = 不知道是什么 = 划走 ✗(实测 300 vs 68,000)|
| 2 | **技术介绍文独立成篇** -- 写一个前沿技术/工程问题的应用,**以我们的产品为例**,自然引出 | 读者的动机是"学点东西",不是"看广告" ✓;产品作为**案例**出现而非主角 ✓ |
| 3 | **系列化 + 钩子** -- 接在前一篇之上的内容,**必须加"上篇/相关阅读"钩子**,方便快速跳转 | 让老读者能接续、新读者能回溯 ✓ 单篇不成系列就攒不出复利 ✗ |
| 4 | **每篇都要能给"路人"看** -- 首屏三段内回答:这是什么 / 给谁用 / 现在能干什么 | 与规则 1 同源,但作用于**每一次发布**(不是只有首篇)|

## 二、三层内容结构(按此排产)

```
第 1 层 · 技术介绍文(引流层,独立成篇,不带产品名也能读)
   └─ 选一个真实工程问题 → 讲清机制与取舍 → 末尾"我们把这个思路做成了一个桌面 AI 伙伴:[链接]"
第 2 层 · 产品概览文(转化层)-- 是什么 / 给谁 / 能干什么 / 一张 hero 图 / 直接下载
第 3 层 · 版本更新文(续接层)-- 必带钩子(上篇 + 概览文链接),开头一句话复述"它是谁"
```

## 三、首篇技术介绍文(大纲,待写全文)

**标题(择一)**
- 《桌面 AI Agent 的"可治理运行时":为什么"管得住"比"会聊天"更重要》
- 《我把 31 个工具塞进一个桌宠之后,最难的居然不是工具本身》

**结构**
1. **钩子**(3 句):AI Agent 一旦能调本机工具,"能做什么"就不再是问题,**"怎么不出事"**才是 ✓
2. **问题拆解**:权限、白名单、审计、成本上限四件事,各自解决什么失效模式
3. **机制**:一次工具调用的完整链路(请求 → 权限判定 → 白名单试算 → 审计留痕 → 成本记账),**附一张流程图**
4. **取舍**:为什么"被拒也要留痕"、为什么"成本按天限额且超限不发请求"(对照"静默烧钱"反例 ✓)
5. **以我们产品为例**:把上面那套落成一个桌面 AI 伙伴(工具生态 + 治理四件套 + MCP 接入)→ 附 Github/下载链接 ✓
6. **钩子**:文末挂"产品概览文"与下一篇预告 ✓

**素材我已备好**:`governance.py` 审计与权限、出网白名单试算、成本限额逻辑、审计窗口截图(可现截 ✓)

## 四、发布纪律（配合上述规则）

- 每篇发布前自检：**首屏三段能不能让完全不知道这个项目的人看懂** ✓（做不到就重写开头 ✗）
- 更新文**必须**带：① 一句“它是什么” ② 上篇/概览文链接 ③ 这次改动对**使用者**的意义（不是改动清单 ✓）

### 渠道（2026-09-22 使用者定：**只做两个，不铺开**）

| 渠道 | 定位 | 注意 |
|---|---|---|
| **知乎** | **主战场（已验证：6.8 万阅读 + 数百赞同收藏 ✓）** | 图文长文、富文本友好；标题与首屏三段是关键 ✓ 代码块用知乎的代码样式（否则排版乱 ✗）|
| **公众号** | 次战场（复用知乎稿） | ✗ **正文里不能放可点外链** → 文末用「阅读原文」接仓库/发布页，或正文写“GitHub 搜 xxx”；图片要压缩（体积限制 ✓）|

**一稿两投的差异处理**（关键，别直接复制）：
1. 开头 200 字要**重写**（知乎读者可点外链、公众号不能 ✗）
2. 公众号：外链→“阅读原文”或文字引导；知乎：外链直接嵌 ✓
3. 两者都保留：hero 图、机制流程图、文末钩子 ✓

### 数据回看
- 发布 **48h** 后记录：阅读 / 赞同（知乎）/ 收藏 / 仓库星标与下载增量 ✓
- 对比基线：**更新文 300 ✗ vs 概览/技术文 68,000 ✓**；同时看仓库流量（与 14 天基线 259 浏览 / 93 克隆对比 ✓）
- 结论写进当日日志 `workspace/memory/YYYY-MM-DD.md` ✓

### 三类视频（与内容策略三层对应）

| 类型 | 时长 | 核心内容 | 圖要求 |
|---|---|---|---|
| **技术介绍型** | 3~5 分钟 | 一个工程问题 → 机制 → 取舍 → 以产品为例 | **最多、最专业**（流程/架构/链路图 + 代码动画）|
| 产品概览型 | 1~2 分钟 | 是什么 / 给谁 / 能干什么 / 一键下载 | hero 画面 + 功能演示录屏 |
| 更新型 | 30~60 秒 | 这次改了 **对使用者的意义**（不是改动清单）+ 勾住上篇 | 前后对比 + 局部高亮 |

### “专业的图”怎么做（关键 —— 不用 AI 生图 ✗）

- **代码生成矢量图**：流程图/架构图/调用链路图 → 统一配色（与产品同一套 token）、统一字重、导出 PNG/SVG ✓
- **截图高亮**：红框/箭头/局部放大，指向具体控件或代码行 ✓
- **数据图**：流量、成本、回合数等曲线（用真实数据 ✓）
- 原则：**图只承载精简流程与关键节点**，完整解释留在配音与字幕 ✓

### 视频节奏模板（可复用）

1. **0~5 秒勾子**：抛出问题（“Agent 能调本机工具之后，什么问题最致命？”）
2. 5~20 秒：它是什么（三句话 + 一张主图）
3. 主体：每段 **3~8 秒一个信息点**，配音 + 字幕 + 图同步；代码段落用高亮逐行 ✓
4. 结尾 10 秒：一句结论 + **文末勾子**（上篇/概览/下载）✓

### **待办：视频剪辑与特效专项调研**（使用者指定）

产出目标：一套**可复用视频模板 + 剪辑 SOP**。调研清单：
1. **工具选型**：全程序化（FFmpeg 技能 ✓ 可重复/可批量）vs 装 GUI 剪辑（精修更快但不可重复）—— 给对比与建议
2. **字幕规范**：字号/位置/断句/中英混排（直接复用视频号惯例 ✓）
3. **配音与节奏**：TTS 语速/停顿；图文声同步表怎么排
4. **特效清单**（从“得体”到“不花哨”）：转场、高亮、局部放大、强调下划线、数字滚动 —— 并明确**哪些不要**（花哨转场/闪动 ✗）
5. **片头片尾模板**：3 秒片头（品牌 + 一句定位）+ 5 秒片尾（仓库/下载址/下期预告）
6. **产出物**：一份 SOP + 一个可填内容的模板工程（脚本 + 素材目录约定）
