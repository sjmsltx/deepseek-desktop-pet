## 0. 结论（先给答案）

**不用截图 OCR，也不用解析 CSS class** ✗ → 采用**三段式机器导出**：

```
① 后端 JSON 接口   ← 协作台 Python 侧提供（我实现）
② 前端行级 data-*   ← 每行必须带 data-id / data-seq / data-layer（我实现）
③ "导出当前视图"按钮 ← 把 UI 内存里渲染用的数据原样导出（我实现）
```

复核方拿到的可比对数据 = **②/③（界面实际渲染）↔ ① /view（后端投影）↔ 日志文件（真相）** 三方比对 ✓

---

## 1. 后端 JSON 接口（冻结）

| 方法 | 路径 | 返回 | 说明 |
|---|---|---|---|
| GET | `/api/view?channel=<c>&layer=L1\|L2\|L3` | `Msg[]` | 与 `RelayLog.view()` 同源；`Msg` 字段逐一对应（`id/seq/ts/channel/sender/recipients/kind/visibility/body/meta`）|
| GET | `/api/inbox?agent=<a>&layer=L1\|L2\|L3` | `Msg[]` | 与 `RelayLog.inbox()` 同源 |
| GET | `/api/snapshot` | `{turn_no, cost_micro, tokens, interrupted, concluded, stopped, warnings}` | 与 `RelayLog.snapshot()` 同源 |
| GET | `/api/log.jsonl` | 原始日志逐行 | **真相源**，供 `replay()` 对照 |

**约束**：接口返回**必须**直接来自内核投影（不得在 HTTP 层做二次过滤/重排 ✗），否则"同源"无从验证 ✓

## 2. 前端行级属性（冻结）

界面上**每一条渲染出来的消息行**必须带：

```html
<div class="row" data-id="<消息 id>" data-seq="<整数>" data-layer="L1|L2|L3" data-kind="<kind>" data-sender="<sender>">
```

- `data-*` 是**唯一**允许复核脚本依赖的选择器 ✓（不依赖 class 名/文案 ✗ —— 文案会改 ✓）
- L2 轨道每行**额外**带：`data-cost-micro` / `data-tokens` ✓（C 组对账要用）
- 暂停/停止/结论等状态节点：`data-state="running|interrupted|stopped|concluded"` + `data-reason="turn_limit|time_limit|token_limit|cost_limit|converged|provider_failed"` ✓（B/D 组断言用）

## 3. "导出当前视图"按钮（冻结）

- 位置：协作台右上角「⤓ 导出视图」
- 产出：`view_export_<layer>_<时间戳>.json`，内容 = **界面当前正在渲染的那份数据**（不是重新去后端拉一次 ✗）
- 用途：证明"界面看到的"与"/view 返回的""日志里的"三者一致 ✓

## 4. 复核方可做的三种独立比对（都属"看渲染结果" ✓）

| 比对 | 取数方式 | 判定 |
|---|---|---|
| 渲染 ↔ 后端投影 | DOM `[data-seq]` ↔ `/api/view` | id 集合相等 + 顺序 = `seq` 升序 ✓ |
| 后端投影 ↔ 日志真相 | `/api/view` ↔ `/api/log.jsonl` 经 `replay()` | 逐条字段一致 ✓ |
| 渲染 ↔ 日志真相 | DOM ↔ `replay()` | 三层并集 = 日志全集（按 id 去重）✓ |

## 5. 明确不做（避免脆弱依赖）

- ✗ 截图 OCR 认字（不可靠、不可复现）
- ✗ 依赖 CSS class / 中文文案 / 像素位置 做断言
- ✗ 让复核方读实现代码来判断"同源"（必须以数据为准）
