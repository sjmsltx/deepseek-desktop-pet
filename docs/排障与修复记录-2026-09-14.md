## 一、用户反映的现象（原话）

> stop 停不了；思考有点放飞、反复打转；思考有时会自己停了；前后文接收理解有问题；输出上限自定义改了、界面没变化，不知道改成功没有。

## 二、根因（已逐条复核，含一处诊断被推翻）

| 现象 | 根因 | 证据 |
|---|---|---|
| stop 停不了 | 代次检查只在**工具轮次边界**，流循环内部零检查；网络层无取消入口 | `desktop_pet.py:2099-2116` 原代码；`deepseek_client.stream_chat_completions` 原无 cancel |
| 放飞 / 打转 | `_stop_ai()` 立刻 `_next_task()` → 旧字流未完（连接没断、仍在计费）＋新任务同时开始，两股输出交错 | 原 `desktop_pet.py:862` |
| 思考自己停 | 代次被顶掉后**静默 return**（不报错、不留痕）；外加两条兜底路径被 `max_tokens` 500/300 截断 | 原 `:2101/2210`；`:2153/2190` |
| 输出上限改了不生效 | **两套真相**：「自定义…」写 `config.json`，而发请求/界面回显读**模型档案** `models.json` | 原 `_set_max_tokens_dialog:4910` vs `settings_ui.py:353`、`desktop_pet.py:2109` |
| ⚠️ `memory_store.py` 的 `Temp.tmp→Temp` 路径 bug | **未在代码中证实**（该文件无 Temp 相关写入）→ 本轮未动，待定位真实报错来源 | 复核结论 |

## 三、已实施改动（v6.53，未发版）

### P0（4 条）
1. **流内可中断**：`deepseek_client.stream_chat_completions(..., should_cancel=None)` 逐块检查，命中即 `return`（关连接 → **停止计费**）；`desktop_pet` 注入"代次是否变了"回调，循环内也逐块检查
2. **`/stop` 不抢跑**：保留线程句柄；停止只置 `_pending_resume`，由退出中的 worker 收尾再接续队列
3. **`自定义…` 走模型档案** + `_sync_settings_ui()` 回填设置窗口（不再"存了界面没变"）
4. **静默 return → 日志**：新增 `_log_ai_abort(stage)` 写入 `pet_log`

### 记忆过拟合治理（用户批准 1+2）
5. **相关性闸门**（`memory_engine`）：新增 `search_detailed()`（命中词数/覆盖率）+ `search_memory_for_injection()`；判据 = 命中 ≥2 个查询 2-gram **或** 覆盖率 ≥0.34，且 BM25 ≥ 0.25×最佳。**没过闸门 → 本轮不注入检索记忆**。常量：`GATE_MIN_MATCHED / GATE_MIN_COVERAGE / GATE_KEEP_RATIO`（可调）
   - ⚠️ 默认 `search_memory()` **行为不变**（回归 C1/C4 兼容）；只有注入路径走闸门
6. **「记忆只作背景」硬约束**：注入块尾部追加规则——仅当问题直接相关才引用、**不要主动把话题引向记忆**、不要为显得"记得"而提及记忆

### 顺带（P1 低成本 2 条）
7. 兜底上限写死 `500/300` → `min(4096, max_tokens)`
8. 临时诊断文件清理
