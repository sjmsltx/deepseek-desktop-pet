# 技能包规范（Skill Pack Spec）· 2026-09-20

> Batch 3-1 交付物。**这份规范是从一个真实技能包（`plugins/office_report/`）跑通后反推出来的**，
> 不是先写规范再找地方用。实现在 `skill_pack.py`，加载与分发仍由既有的 `plugin_manager.py` 负责。

## 1. 定位：扩展现有插件系统，不另立一套

桌宠 v6.21 起已有插件系统：`plugins/<name>/plugin.json` + `plugin.py`，五类（tool / menu / rules /
theme / skill）、加载分发、JSON + ast + 危险关键词三道闸、AI 侧 `install_plugin` / `list_plugins` /
`uninstall_plugin` 工具。

> **v6.71 补**：权限扫描增加「文件读写 API 必须声明」—— 关键词判据漏了 `open()`，
> 实测零权限包能任意读文件（含 `config.json` 里的 API key）并覆盖程序目录文件；详见第 3 节。

本次只补三件缺的：

| 补什么 | 为什么需要 |
|---|---|
| **权限声明** | 老系统只有"危险关键词一律拒"，于是合法技能（要跑子进程/联网/写文件）永远装不上，或者只能偷偷绕过 |
| **打包与校验** | 老系统只能由 AI 传字符串安装，没有 zip/GitHub 来源、没有体积与路径校验、没有来源与哈希登记 |
| **可管理** | 老系统只能"装了/删了"，没有启停、没有来源版本、卸载是 `rmtree` 直接删（不可恢复） |

## 2. 清单文件（plugin.json）

沿用文件名，新增字段**全部可选** —— v1 老插件照旧能用。

```json
{
  "manifest_version": 2,
  "name": "office_report",
  "title": "办公报表",
  "version": "1.0.0",
  "author": "AutoClaw 官方",
  "description": "把结构化数据交给本机 WPS / Office 生成 xlsx 与 PDF 报表",
  "type": "tool",
  "entry": "plugin.py",
  "enabled": true,
  "builtin": true,
  "license": "MIT",
  "min_pet_version": "6.67",
  "permissions": {
    "office.com": "调用本机 WPS / Office 的 COM 接口生成表格与 PDF",
    "files.write": "把生成的报表写到程序目录的 输出/ 下"
  },
  "tools": [ { "name": "excel_report", "description": "…", "parameters": { } } ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 唯一 id，同时是目录名：字母/数字/下划线/连字符，≤32 |
| `type` | ✅ | `tool` / `menu` / `rules` / `theme` / `skill` |
| `manifest_version` | — | 缺省按 1 处理（宽松模式）；写 2 才启用权限严管 |
| `entry` | — | 包内相对路径、只允许 `.py`；禁止 `../` 与绝对路径 |
| `permissions` | — | 权限类别 → **人类可读的申请理由**（理由必填，否则使用者无法判断该不该批） |
| `builtin` | — | 随程序一起发布的官方包：视为作者已授予所声明权限，不要求现场确认 |
| `enabled` | — | 缺省 true |
| `min_pet_version` / `version` / `author` / `license` / `homepage` | — | 元信息，用于界面展示与兼容判断 |

## 3. 权限模型（三层）

**权限类别（当前 8 类）**

| 类别 | 覆盖的能力 | 典型场景 |
|---|---|---|
| `files.read` | 读文件 | 读配置、读素材 |
| `files.write` | 建/改/删文件 | 把结果写到 `输出/` |
| `office.com` | 驱动 WPS / Microsoft Office（COM） | 生成表格、导出 PDF |
| `network` | 联网 | 下载数据、调外部服务 |
| `process` | 起子进程 / 运行外部程序 | 调 ffmpeg、调系统命令 |
| `audio` | 播放语音 / 用麦克风 | 语音播报 |
| `clipboard` | 剪贴板读写 | 取剪贴板内容 |
| `ai.calls` | 调模型（会产生费用） | 用模型做后处理 |

**第一层：永禁（写任何权限都不放行）**
`os.system`、`eval(`、`exec(`、`compile(`、`__import__`、`winreg`、`ctypes.windll`、`SendKeys`、
`pyautogui`、`shutil.rmtree`、`os.kill`、`ctypes.CDLL`、`pickle.loads`、`marshal.loads`。
理由：这些要么能直接破坏系统，要么能绕过沙箱，没有任何正常技能需要它们。

**第二层：分级关键词 → 必须声明**
`subprocess` / `os.popen` → 需 `process`；`os.remove` / `os.replace` / `shutil.move` … → 需 `files.write`；
`urllib.request` / `requests.*` / `socket` → 需 `network`。
代码里出现但 manifest 未声明 → **拒绝安装**（报错信息直接告诉作者缺哪个类别）。

**第二层补丁（v6.71）：文件读写 API 也必须声明** —— 关键词判据里**没有 `open()`**，
实测（2026-09-20 端到端验证）一个「声明零权限」的包可以：① 安装即启用、无需确认；
② 读任意文件（包括程序目录下的 `config.json` —— 里面有使用者的 API key）；
③ 往程序目录写文件（等于能覆盖 `config.json` 或程序自己的代码）。
现在用 **AST 精确识别**（`skill_pack.file_api_permissions`）：

| 写法 | 需要的权限 |
|---|---|
| `open(p)` / `open(p, 'r')` / `Path(p).read_text()` / `pd.read_csv(p)` | `files.read` |
| `open(p, 'w'/'a'/'x'/'r+')` / `Path(p).write_text()` / `os.remove/makedirs/replace` / `shutil.copy/move` | `files.write` |

规则细节：① 只读时声明 `files.read` **或** `files.write` 都算声明过文件权限（不重复索要）；
② 写入必须显式声明 `files.write`；③ **不收 `replace`/`rename`/`chmod` 这些方法名**——
`str.replace()`、`DataFrame.rename()` 会同名误报；④ `manifest_version=1` 老插件仍只拦永禁，不受影响。

**第三层：确认与运行时**
安装时列出权限卡片（类别 + 理由 + 来源）→ 使用者确认；**未确认完的包不加载**（登记为 `pending`）；
卸载随时可做。写类操作的逐次二次确认由调用方（界面/工具）决定，本层不强制。

### 向后兼容（重要，已被实战验证）
- `manifest_version` 缺省（v1 老插件）→ **只拦永禁，不做分级**。否则老插件会被新规误伤。
  （本轮实际踩到：`plugins/vision/plugin.json` 用 `urllib.request` 却没声明权限，接入新策略
  后被直接拒载 —— 已修：加载器对 v1 宽松 + 给 vision 补上 `manifest_version: 2` 与 `network` 声明。）
- 装到硬盘上的 v2 包若声明了权限但没有登记记录、且不是 `builtin` → 视为"手工塞进来的"，同样要求先确认。

## 4. 安装来源与校验

| 来源 | 入口 | 说明 |
|---|---|---|
| 本地目录 | `install_from_dir` | 目录里必须有 `plugin.json` |
| 本地 zip | `install_from_zip` | 自动剥掉 GitHub 那层 `owner-repo-ref/` 外层目录 |
| GitHub 仓库 | `install_from_github` | `owner/repo[@ref]` → `codeload` zip；下载函数可注入（便于离线测试） |
| AI 通道 | `plugin_mgr.install()` | 保留老通道（模型直接给 manifest + 代码），但也走同一套校验 |

**校验清单（缺一项就拒绝）**

1. manifest：必填字段、类型、权限类别合法性、entry 必须是包内 `.py`
2. 入口代码：语法（`ast.parse`）→ 永禁扫描 → 分级扫描（需声明）
3. zip：包内路径禁止 `../` / 绝对路径 / 盘符（zip-slip）；扩展名白名单；
   文件数 ≤ 200；解包后体积 ≤ 5 MB；zip 本身 ≤ 5 MB
4. 落盘后：算包内容哈希（16 位）登记，来源与安装时间一并记录，便于日后发现"包被人改过"

## 5. 目录布局与登记

```
plugins/
├── office_report/          # 官方技能包（builtin）
│   ├── plugin.json
│   └── plugin.py
├── vision/                 # 老插件（已补 v2 清单与 network 声明）
├── _registry.json          # 登记表：版本/来源/时间/哈希/权限(声明, 已确认, 待确认)/启用
├── _uninstalled/           # 卸载停放区：demo-20260920-123335/（保留最近 5 个，可手动找回）
└── _tmp/                   # 安装临时目录（解包/下载，用完即清）
```

`_` 前缀目录一律不当作技能包扫描；`_registry.json`、`_uninstalled/`、`_tmp/` 已进 `.gitignore`。

## 6. 管理接口

```python
import skill_pack as sp
sp.validate_manifest(meta)                    # -> (ok, msg, normalized)
sp.scan_code(src, declared, strict=True)      # -> (ok, msg, needed_permissions)
sp.install_from_dir(d, plugins_dir, granted=[...])
sp.install_from_zip(z, plugins_dir, granted=[...])
sp.install_from_github('owner/repo', plugins_dir, granted=[...])
sp.grant_permissions(plugins_dir, name, ['office.com'])
sp.set_enabled(plugins_dir, name, True)       # 未确认权限时拒绝启用
sp.uninstall(plugins_dir, name)               # 进停放区，不直接删
sp.list_packs(plugins_dir)                    # 界面数据：状态/来源/版本/权限
sp.permissions_card(plugins_dir, name)        # 安装前给人看的权限卡片
```

模型侧对应一个工具：`skill_pack`（action = list / info / install / grant / enable / disable / uninstall），
放在**进阶工具集**（不是日常高频，避免每请求多花上下文）。

## 8. 官方技能包（随程序自带）

| 技能 | 工具名 | 声明权限 | 能做什么 |
|---|---|---|---|
| 办公报表 | `excel_report` | `office.com` `files.write` | 结构化数据 → 带样式 xlsx + PDF（WPS/Office COM） |
| PDF 工具 | `pdf_tool` | `files.read` `files.write` | 合并 / 按页拆分 / 提取文字 / 看信息（pypdf，纯本地） |
| 图片批处理 | `image_batch` | `files.read` `files.write` | 等比缩放 / 转格式 / 序号重命名（Pillow，只复制不改原图） |
| 文件整理 | `organize_files` | `files.read` `files.write` | 类型或日期归类 / 找重复（只报告）/ 重命名；**先预览、`confirm=true` 才动文件** |

内置 `office_doc` 工具另补了两个动作（不是技能包，属日常核心能力）：
`write_doc`（Word：标题/段落/项目符号/表格，python-docx）、
`write_slides`（PPT：封面/要点页/讲稿备注，python-pptx）—— 都不依赖本机装 Word/PPT。
