## 1. 一句话概述

**多个 AI（可来自不同厂商、可各自使用独立密钥）在同一处协作**：人 + 若干 AI 角色在**大厅**里按 `@` 点名互动；**完整输出归各角色自己的会话通道**，大厅只承载**点名、简要总结与投递回执**。

## 2. 相对 v1 的四处变化

| # | v1 | v2.1 |
|---|---|---|
| 1 | 群聊直接显示全部内容 | **群聊只做「@ 通道 + 简要总结 + 投递」**；**全文归各角色通道** |
| 2 | 外部渠道待定 | **不做 QQ / 微信接入**（仅参考其交互形式：群聊 + @ + 私聊） |
| 3 | 投递机制待新建 | **采用「文件通道（明文通道）+ 静默投递」** —— 该机制已由内部多线协作实践验证 |
| 4 | 仅群聊 | **支持与单个 AI 角色 1v1 通话** |

## 3. 架构：双视图 + 三通道

| 层 | 内容 |
|---|---|
| 视图① **大厅** | `@` 点名（**经人工确认后发出**）· 简要总结 · 投递回执 |
| 视图② **角色通道** | 每个 AI 角色一条通道，显示**全文**；独立上下文 / 模型 / 密钥；**持久化 + 可回放** |
| 视图③ **单聊** | 直接与某角色 1v1（直连模型 API） |
| **传输层** | 文件通道 + 静默投递（复用 3.0 M1 消息内核） |
| **身份与治理** | 每角色 = 模型档案（服务方 + 密钥 + 参数 + 限额）；额度上限、审计、白名单 |

## 4. 上下文策略（多 agent 场景）：三层存储 + 五优先级

### 4.1 三层存储

| 层 | 存什么 | 可见范围 |
|---|---|---|
| **L0 全文** | 每个角色通道的完整记录（文件、可检索、可回放） | 人；**默认不进模型** |
| **L1 摘要层** | 每条发言的**一句话摘要 + 指向原文的指针** | 大厅视图；按需进模型 |
| **L2 工作集** | 本轮实际送入模型的内容 | 模型 |

### 4.2 选择优先级（从高到低）

1. **点名 / 引用** = 强信号 → 必进（含被引用片段）
2. **本角色参与的线索** → 进
3. **时效窗口**（最近 N 轮 / T 分钟）→ 进
4. **相关性**（关键词 / 向量检索）→ 进（设上限）
5. **预算裁剪**：超 token 上限时，**先砍"与本角色无关的全文"，保留摘要 + 指针**

### 4.3 关键手法：摘要常驻 + 原文按需

- 送入模型 = 本角色系统提示 + **自身近段全文** + **大厅摘要卡** + **被点名/被引用片段**
- 需要细节时由模型**按需拉取**（工具化读取 L0）
- **归属隔离**：其他角色的私聊全文**默认不进入**本角色上下文（防串味）

## 5. 交互与安全闸门

1. **人工确认闸门**：角色之间**可以互相 `@`**，但 **@ 之后必须由使用者手动确认才真正发出**
2. **每轮只出一条摘要卡**（防刷屏）
3. **默认不做"自主无限互聊"**（成本不可控）
4. **额度**：每角色独立上限 + 全局上限；超额即停并提示

## 6. 与主线的关系

共用底座：会话内核 · 投递 · 渠道抽象 · 模型档案 · 治理三件。
本支线负责：**多角色协作的视图、上下文装配与闸门**。

## 7. 分期路线

| 期 | 内容 |
|---|---|
| MVP 第一刀 | 大厅 + 角色通道 + 单聊；`@` 需人工确认；规则模板摘要；本地"遥控通道"（手机侧以 IM 消息驱动桌面端） |
| 第二刀 | 最小存储/装配器（L0/L1/L2 + 五优先级 + token 预算） |
| 后续 | 局域网直连；议长模型生成摘要；向量检索增强 |
| 明确不做 | QQ / 微信接入；自主无限互聊 |
