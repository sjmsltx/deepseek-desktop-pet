三、剩余可拆项评估（收益 vs 风险）

✅ 建议继续拆 · 工具执行器 tools_executor.py 中风险 · 高收益

_execute_tool 的 if/elif 分发 + 28 个工具 handler（_smart_open/_web_search/_read_own_file 等）→ 拆为独立模块，通过 context 对象访问状态。

收益：主文件 -500 行；工具逻辑可独立单测（本次 400 排查中工具链路测试困难正源于此）。风险：handler 深度耦合 self 状态，需 1-2 小时精细迁移。

✅ 建议继续拆 · system prompt 构建 低风险 · 中收益

_ai_worker 内 80+ 行 system prompt 拼接（身份/性格/记忆/待办/插件规则/好感度/工具规则）→ 参数化拆到 prompt_builder.build_system_prompt()。

收益：主文件 -80 行；prompt 模板与业务逻辑分离，改提示词不动主文件。风险：低（纯字符串拼接）。

⚠️ 不建议拆 · 动画/立绘系统 高风险 · 低收益

呼吸/眨眼/呆毛动画与 QTimer + 立绘状态深度交织，拆出后无法脱离 UI 测试，收益仅是「行数好看」。

⚠️ 不建议拆 · 聊天面板/子窗口构建 中风险 · 低收益

一次性 Qt 布局构建代码，拆出去不可复用、不可单测，且容易在拆分中破坏布局细节（刚修完的折叠/流式 bug 就属于该区域）。
