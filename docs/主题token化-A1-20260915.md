# 主题 token 化 · A1 记录（2026-09-15）

> 目标：把「改外观」从**改源码**变成**改 token / 装主题**，消除 AI 改 UI 时定位不准的结构性原因。

## 一、问题（改前的实测事实）

| # | 事实 | 证据 |
|---|------|------|
| 1 | 主题色**内联**在主程序 `desktop_pet.py`（`DEFAULT_THEME` 17 项） | — |
| 2 | 设置窗口 `settings_ui.py` **另写了一套配色**（`#14161f`、`rgba(255,255,255,0.05)` 等 14 处）→ **主题源不唯一** | `settings_ui.py:_apply_theme` |
| 3 | 主题只作用于**聊天面板 + 气泡**（`_panel_qss` 只管 5 个控件） | `desktop_pet.py:_panel_qss` / `_apply_theme` |
| 4 | 小游戏 / 关系面板 / 卡片**完全不接主题**（全文 `theme` 命中 0 次） | `pet_minigames.py`、`affection_ui.py`、`chat_cards.py` |
| 5 | system prompt 声称「UI 样式（……**所有**颜色）都在主题系统里」——**与事实不符** | `prompt_builder.py` |
| 6 | 全项目硬编码颜色 **172 处 / 11 个文件**（含主程序内 `DEFAULT_THEME` 17 处） | AST 扫描 |

后果：AI 遇到「改 UI 某个东西」时陷入两难——按规则该走主题，但目标处**没有 token**；想改源码，规则又**禁止**。于是只能猜，表现为**定位不准**。

## 二、A1 做了什么（低风险止血，不动渲染）

1. **建立唯一 token 源 `pet_theme.py`**（17 → **28** 个 token）
   - 主程序改从该模块 import（保留 `DEFAULT_THEME` 名字，既有引用零改动）；
   - 设置窗口的 11 处写死配色提升为 token（`dialog_bg` / `list_*` / `item_*` / `popup_*` / `hint_text`），**取值与原字面量逐项一致**；
   - 附 `TOKEN_GROUPS` 分类索引（panel / bubble / dialog / minigame / cards / relation），后三类标注「A2 待接入」。
2. **设置窗口改为全 token 取色**：`host.theme` 同名键优先（含 theme 插件覆盖），其余取默认值。
3. **system prompt 改为诚实口径**：颜色**优先走主题**，唯一源是 `pet_theme.py`；**只有该文件确实没有对应 token 时**才允许改源码，且必须 `search_code → read_file(带行号) → edit_own_code(按行)`，并在回复里报出改了哪个文件哪几行。
4. **新增护栏测试 `tests/test_theme_tokens.py`**（5 项）
   - 唯一源存在、主程序不再内联；
   - token 值/分组合法、无未归类 token；
   - 设置窗口零硬编码颜色；
   - prompt 必须指明 token 源与「无 token 才允许改源码」；
   - **硬编码颜色只减不增**（ratchet，基线 `tests/golden/theme_hardcoded_baseline.json`，当前余量 **145 处**）。
