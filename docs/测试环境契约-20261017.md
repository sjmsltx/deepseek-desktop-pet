# 测试环境契约（全量测试的唯一合法口径）

- 生效日期：2026-10-17
- 依据：Owner 2026-10-17 23:05「契约有必要定，得统一口径并且留痕」
- 适用范围：本仓库**所有** `python -m pytest` 的全量运行（本地、他人、AI 助手一律适用）

---

## 一、规定（只有一条，但必须照做）

跑全量**必须**同时满足两件事：

1. 设环境变量 `PYTHONIOENCODING=utf-8`
2. 用 `tools/ac_lock.py` 外层拿锁

完整命令（PowerShell）：

```powershell
$env:PYTHONIOENCODING = "utf-8"
python tools\ac_lock.py --name 全量 --wait 300 -- python -m pytest -q
```

**通过标准**：`rc=0`，输出形如 `N passed, M skipped`，**不允许出现 failed / error**。

**稳定性要求**：跑前跑后各记一次 `git rev-parse --short HEAD`，两次不一致 ⇒ 结果作废重跑
（中途有人提交时，跑出来的红绿都不可信）。

---

## 二、为什么必须有这条契约

2026-10-17 实测：**同一天、同一份代码，换一个环境变量就换一批红。**

| 环境 | 实测结果 | 失败类型 |
|---|---|---|
| 不设任何变量（GBK 控制台） | 13 failed / 1307 passed | `asset_ops` / `cli_paths` / `pending_protocol` 等，都与中文路径或子进程输出有关 |
| **`PYTHONIOENCODING=utf-8`** | **1320 passed / 9 skipped（rc=0）** | —— |
| `PYTHONUTF8=1` | 4 failed / 1316 passed | `test_a4_*`×2 / `test_ac_lock` / `test_mcp` |

三套环境互不兼容。**不定契约，任何"全绿"都无法被别人复核** —— 谁都可以换一套环境跑出一个不同结论。

---

## 三、已查明的两个根因（均已修复）

### 3.1 `tools/` 下 emoji 打印在 GBK 控制台崩溃

**现象**：`ac_lock.py` 在**启动第一句**就抛 `UnicodeEncodeError`（`print('🔒 ...')`），
测试根本没跑（用时 0 秒）；`aclock_plugin.py` 在 `pytest_unconfigure` 阶段崩，
导致每次全量收尾异常退出；重定向到文件时更糟 —— **结果行随未刷新的缓冲区一起丢失**，
等于拿不到本次全量的结论。

**修法**：两文件统一改走 `_safe_print()`：先试 `msg.encode(enc)`，编不了就降级成 `?`，不抛异常。

**为什么不直接删 emoji**：UTF-8 控制台下 emoji 可读性更好；只在编不了时降级。

### 3.2 嵌套 pytest 用例的解码依赖外部环境

`tests/test_a_stage.py::test_subpytest_inherits_nested_marker` 里，
**内层**那个 `subprocess.run(..., text=True)` 没指定 `encoding` ⇒ 用 `locale`（GBK）解码；
而外层若设了 `PYTHONIOENCODING=utf-8`，内层子进程按 utf-8 输出 ⇒ 解码崩 ⇒ 假红。

**修法**：内层显式 `env["PYTHONIOENCODING"]="utf-8"` + `encoding="utf-8", errors="replace"`，
外层也加 `errors="replace"`。修后该用例在契约环境下 **1 passed**。

## 四、契约定了之后，这四件事别做

| 别做 | 为什么 |
|---|---|
| 不加 `PYTHONIOENCODING` 直接跑全量 | 会得到 13 failed，且失败项与代码无关 |
| 改用 `PYTHONUTF8=1` | 那会换出另外 4 个失败（a4 / ac_lock / mcp），它们在该环境外是绿的 |
| 不带 `ac_lock.py` 跑 | 项目 `pytest.ini` 虽会自动拿锁，但外层锁是"跑全量"的唯一凭证；且并发跑会互撞 |
| 用 `runpy` / 自写 runner 在进程内启动 pytest | `sys.argv[0]` 形状被改变 ⇒ 干扰 `test_cli_paths` / `test_asset_ops` 这类检查 CLI 路径的用例（实测造出 12 个假红） |

## 五、自检（30 秒）

跑完看一眼这三样即可：

1. `rc=0`？
2. 结果行是 `N passed, M skipped` 且 **failed 数为 0**？
3. 跑前跑后的 HEAD 一致？

三样都满足，才算"这次全量是干净的"。

---

## 六、如果换了机器 / 换了 Python 版本

本契约基于 **Windows + 中文控制台（GBK 默认）** 这一前提。
换到纯 UTF-8 环境（Linux / macOS / Windows 开了 UTF-8 全局）时：

- `PYTHONIOENCODING=utf-8` 仍然应当设置（保持口径一致，避免"换机器就换结论"）
- 若发现新的环境相关红，**先按本文档的对比表重跑三套环境**，确认是环境还是代码，
  再决定改哪边 —— 不要直接改测试让它变绿
