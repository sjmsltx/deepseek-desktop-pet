三、重新架构：桌宠版四层记忆

层职责存储注入方式
工作记忆当前对话上下文chat_history_{role}.json最近 N 条 + 摘要（保留，优化摘要粒度）
情景记忆对话中的事件/经历memories.json（升级）最近事件 top-k + 按日期分组
语义记忆用户长期事实（画像）memory.json（升级）core 常驻（重要度+recency） + 检索 top-k
程序记忆行为偏好规则facts 中 role=behavior 类随 core 常驻（如「用户不懂英语」→ 规则）

三大核心升级

升级做法借鉴
① 检索注入问话触发：关键词检索（BM25 纯 Python 零依赖）→ LLM 重排 top-3，替代全量注入mem0.search
② 自动抽取对话结束后低频（每 N 轮/空闲时）：LLM 从对话提炼「值得记住的事实/事件」→ 写入语义/情景层mem0.add + Letta 自我编辑
③ 分层预算core（用户画像 ≤400 字符常驻）+ 检索注入（≤600）+ 情景（最近 3 条）；recency 加权Letta core/archival/recall

四、可行性评估（桌面应用约束）

方案可行性说明
关键词检索 BM25✅ 立即可行纯 Python 实现（词频+逆文档频率），零依赖零成本，对中文可做分词简化（n-gram）
LLM 重排序✅ 立即可行复用 deepseek_client，候选 5-8 条让 LLM 选 top-3，每次 +0.5-1k tokens
本地 embedding⚠️ 环境受限fastembed/onnxruntime 在 Python 3.14 无预编译包（rembg 教训）；需等支持或换 3.10 环境做独立服务
自动抽取✅ 立即可行复用 deepseek_client；低频批量（积 5 轮对话或空闲时抽一次），成本可控
向量数据库❌ 不引入chroma 等太重；数据量几百条，numpy 余弦足够
知识图谱❌ 暂缓Zep 图引擎太重；关系可用「标签字段」轻量替代
关键约束：Python 3.14 装不了 onnxruntime → 本地 embedding 受阻。降级路径：Phase1 用 BM25 + LLM 重排（不依赖 embedding 也能显著改善检索），Phase2 等 onnxruntime 支持 3.14 再上 embedding。

五、分期实施路径

Phase 1 · 检索 + 自动抽取 低风险 · 核心收益

memory_engine.py 独立模块：BM25 索引（memory.json 构建）→ 问话时检索 top-k → LLM 重排；对话后自动抽取事实/事件（低频批量）；分层注入（core + 检索 + 情景）。

效果：「我下午干什么」→ 检索命中「下午上课」→ AI 回答。事实再多也不全塞 prompt。

Phase 2 · 语义增强 中风险 · 环境依赖

本地 embedding（fastembed，待 onnxruntime 支持 3.14）替换/补充 BM25；recency 加权；记忆去重合并（mem0 linking）。

Phase 3 · 关系与反思（可选）

实体关系（桃片→合川→老家→西南大学）；定期记忆反思（LLM 整合重复事实）；记忆可视化面板。
