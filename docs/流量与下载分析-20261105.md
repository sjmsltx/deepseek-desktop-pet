## 五、下载分布（终身累计，不换算日增量）

| 版本 | 发布日 | 天数 | 下载 | 平均/天 | 备注 |
|---|---|---|---|---|---|
| v1.1.0 | 08-04 | 93.5 | 106 | 1.13 | 最早公开版 |
| **v2.9.1** | 09-21 | 45.6 | **349** | 7.65 | **占 65%** |
| v3.0.0 | 10-21 | 15.3 | 24 | 1.57 | 预发布 |
| v3.0.1 | 10-30 | 6.9 | 29 | 4.19 | |
| v3.0.2 | 11-02 | 3.6 | 26 | **7.18** | 最新，势头最好 |
| 合计 | — | — | **534** | — | |

### 5.1 怎么读这张表

⚠ **「平均/天」不是日增量，是「终身累计 ÷ 发布天数」**，早期高峰已摊平在里面。
所以**不能**拿 v3.0.2 的 7.18 去说「已经超过 v2.9.1」——v2.9.1 的数字被 45 天平摊过。

能说的只有：**v3.0.2 上线 3.6 天拿 26 次，是目前最快的单版起步**（v3.0.1 是 6.9 天 29 次）。

### 5.2 三连发摊薄

| 版本 | 独占窗口 | 拿到下载 |
|---|---|---|
| v3.0.0 | 10-21 → 10-30（9 天） | 24 |
| v3.0.1 | 10-30 → 11-02（3 天） | 29 |
| v3.0.2 | 11-02 → 现在 | 26 |

v3.0.1 只当了 3 天「最新版」就被 v3.0.2 顶掉。**每个版本都没等到自己的搜索索引建立期**。
对照 v2.9.1 当了 40 天最新版 → 349 次。这两件事很可能是同一件事的两面。

⚠ 这是**相关性**，不是因果。没做对照实验，不下结论。

### 5.3 一件很轻但有效的事

v2.9.1 那页仍然每月拿走几十次下载。在该 release 描述**顶部加一行「这是旧版，最新版 ↗」**，
是一分钟的事。⚠ 这是 GitHub 写操作，按规矩我先报备，等你点头。

## 八、我不确定的（写清，不装懂）

1. **克隆数为何远高于下载数**：14 天 438 次克隆，同期 v3 三版合计 79 次下载。
   可能是爬虫/镜像站，也可能是有人克隆源码自己构建。
   **没有证据，不下结论。** 判据：若某个 IP 段占多数，基本可确定是机器人。
2. **10-24 克隆 112、11-01 克隆 2**：两个极端值都没有机制解释。
3. **发版密度与下载摊薄的关系**：只有 3 个版本的相关性，样本太小，不能当因果。
4. **`watchers=0` 是否真的等于「没有推送渠道」**：GitHub 的 watch 有「仅关注 releases」等选项，
   `subscribers_count=0` 表示连那些也没有。但这不包括 star 用户收到 release 邮件（star 不触发）。
5. **本次分析未包含**：`git clone` 来源 IP（API 不提供）、Star 的时间分布（API 不提供历史）。
